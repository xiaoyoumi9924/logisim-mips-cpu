## 1. 环境准备

### 1.1 版本要求

| 项目 | 要求 |
| --- | --- |
| 仿真软件 | **Logisim-evolution 3.9.0**（必须；工程文件里记录了 `source="3.9.0"`） |
| 系统 | Windows / macOS / Linux 都可以，只要能装 Logisim-evolution |
| Java | 安装包自带，不需要单独装；只有用命令行模式（自检脚本）才需要系统 JRE 17+ |

老版本的 Logisim（原作者 cburch 的那个版本）不认识 Logisim-evolution 新增的元件，
打开会出现大量红叉或者直接报错，**不要用**。

### 1.2 获取安装包

**Windows 用户（推荐）：仓库里已经带了安装包，不用上网下载。**

| 位置 | 文件 | 说明 |
| --- | --- | --- |
| 仓库内 | `tools/logisim-evolution-3.9.0-x86_64.msi` | 官方 v3.9.0 Windows 64 位安装包（约 81 MB），自带运行库 |
| 课程资料 | 老师发的 `logisim-evolution-3.9.0-x86_64.zip` | 解压后里面就是上面这个 MSI |

**macOS / Linux**：上面这个 MSI 只适用于 Windows，请到发布页
<https://github.com/logisim-evolution/logisim-evolution/releases> 找到 **v3.9.0**，
下载对应平台的安装包：

| 系统 | 下载文件 | 说明 |
| --- | --- | --- |
| macOS | `logisim-evolution-3.9.0-*.dmg` | 按芯片选 aarch64（M 系）或 x86_64（Intel） |
| Linux | `...-3.9.0-*.deb` / `.rpm` / `.AppImage` | 也可以直接下 `-all.jar` 用 `java -jar` 运行 |

### 1.3 安装（Windows）

1. 双击 `tools/logisim-evolution-3.9.0-x86_64.msi`（从 zip 包里解压出来的就是这个文件）；
2. 弹出 **UAC 管理员权限提示时点「是」**——MSI 默认装到
   `C:\Program Files\logisim-evolution`，并且要写注册表来注册 `.circ` 文件关联，
   所以必须要管理员权限，这是正常现象；
3. 一路「Next」→「Install」装完，从开始菜单启动即可；
4. 装完之后，也可以直接双击 `.circ` 文件打开（右键 → 打开方式 → Logisim-evolution）。

卸载：设置 → 应用 → 找到 Logisim-evolution → 卸载；免安装版直接删文件夹。

### 1.4 免安装方式（可选）

如果你没有管理员权限，或者不想往系统里装东西，可以用仓库里的脚本，从**同一个官方
安装包**里解出一份免安装版：

1. 仓库里的 `tools/logisim-evolution-3.9.0-x86_64.msi` 就是它，脚本会自动找到；
   也可以用课程发的 `.zip`，放到仓库的 `_local/` 目录（该目录不会提交到仓库）；
2. 执行：

   ```powershell
   pwsh -File tools\setup-logisim.ps1
   ```

3. 脚本会把程序、jar 和自带 JRE 解到 `tools/logisim-evolution-3.9.0/`；
4. 之后用 `scripts\logisim.cmd` 启动，或者 `scripts\logisim.cmd circuits\4.1-单周期CPU.circ`
   直接打开某个电路。

原理：官方 MSI 是 jpackage 打包的，里面包含一个 CAB 包。脚本读取 MSI 的文件表和目录
表，把 CAB 里的文件按真实目录结构还原出来（相当于「绿色版」），全程不写注册表、
不动 Program Files，删掉文件夹就是完全卸载。

> 注意：这个免安装版**没有 `java.exe`**（jpackage 生成的镜像里只有 `jvm.dll`，图形
> 启动器够用）。所以命令行模式（下面的自检脚本）需要系统里另外装一个 JRE 17+。

## 2. 打开与调试电路

### 2.1 打开工程

`文件 → 打开`，选择 `circuits/` 下的 `.circ`。左侧是电路列表，可以点击切换子电路
（比如单周期 CPU 里的 `ALU`、`CU` 都是独立子电路，可以单独打开看）。

### 2.2 时钟与复位

- 工具栏上的**时钟按钮**（或用 `Ctrl+T`）手动打一个节拍，适合一步一步观察；
- 也可以在菜单里把时钟设成自动翻转（Tick Frequency），让它自己跑；
- `main` 电路一般有两个输入引脚：`clk`（时钟）和 `reset`（复位）。先用复位清零，
  再开始打时钟，结果更可控。

### 2.3 观察中间结果

工程里用三种方式显示结果：

- **Hex Digit Display**（数码管）：显示 PC、指令、ALU 结果、寄存器值等，每片显示 4 bit；
- **LED**：显示单个控制信号或标志位；
- **探针 / 引脚**：鼠标悬停在导线上会显示当前值，适合查某个信号为什么不对。

### 2.4 修改指令 ROM 里的程序

两个 CPU 的指令存储器都是 ROM 元件。右键 ROM → `编辑内容`（Edit Contents），
可以按十六进制直接改指令，改完再打时钟就能看到新程序的效果。ROM 的地址按**字**
编址，一条指令占一个字。

### 2.5 导出图片

`文件 → 导出为图片`（Export As Image）可以导出 PNG，用来写实验报告或者在 README
里展示。欢迎把截图放到 `docs/images/`。

## 4. 电路详解

### 4.1 2.2 计数器

**子电路**：`count13`（计数器本体）、`count_pro`（显示演示）

| 子电路 | 引脚 |
| --- | --- |
| `count13` | `cp`(1 入)、`Q0`~`Q3`(各 1 出)、`cout`(1 出) |
| `count_pro` | `cp`(1 入)、`oH`(4 出)、`ol`(4 出)、`LED`(1 出) |

**实现**：4 个 J-K 触发器级联成 4 位计数器，配上与门、或门、非门和反馈逻辑，
把计数状态限制在 0~12；再来一个时钟沿就回到 0，同时 `cout` 输出进位。

**怎么看**：给 `cp` 打时钟，观察 `Q3..Q0` 的二进制变化，数到 1100（12）后下一拍变
0000、`cout` 拉高。`count_pro` 把高位、低位分别接数码管，还用一个 LED 指示进位。

### 4.2 2.3 乘法器

**子电路**：`muti`（主控）、`control`、`shift`、`Add_1`、`Add_7`

| 子电路 | 引脚 |
| --- | --- |
| `muti` | `muti_op1`(8 入)、`muti_op2`(8 入)、`reset`(1 入)、`cp`(1 入)、`count`(4 出)、`product`(8 出) |
| `control` | `cin`(4 入)、`res`(8 入) → `product`(8 出) |
| `shift` | `a0`(8 入) |
| `Add_1` | `A`、`B`、`C`(入) → `S`、`cout`(出)，一位全加器 |
| `Add_7` | `a0`(7 入)、`b0`(7 入) → `cout`(出)，7 位加法进位链 |

**实现**：经典的「移位-相加」算法。每一位乘数决定是否把被乘数累加到部分积上，
然后整体右移一位；4 位计数器记录已经处理了多少位，计满就得到 8 位乘积。

**怎么看**：先在 `main` 电路上给 `a`、`b` 两个 8 位输入赋值，按一下 `reset`，
然后连续打时钟，观察 `count` 从 0 数到 8、`product` 逐步收敛到 `a × b`。

### 4.3 3.1 寄存器堆

**子电路**：`MIPS_32x32_reg`（顶层读写口）、`group_0`、`group_123`（寄存器组）

| 子电路 | 引脚 |
| --- | --- |
| `MIPS_32x32_reg` | `raddr1`、`raddr2`(各 5 入)、`waddr`(5 入)、`wdata`(32 入)、`wen`(1 入)、`cp`(1 入) → `rdata1`、`rdata2`(各 32 出) |
| `group_0` / `group_123` | 每组含 8 个 32 位寄存器的输出、`inner_waddr`(3 入)、`group_en`(1 入)、`wdata`(32 入)、`cp`(1 入) |

**实现**：32 个寄存器拆成 4 组、每组 8 个——第 0 组用 `group_0`，第 1~3 组用
`group_123`。地址的高 2 位选组（`group_en`），低 3 位选组内寄存器
（`inner_waddr`）。两个读端口是纯组合逻辑，写端口在 `cp` 上升沿、且 `wen=1`
时写入。

**怎么看**：设好 `waddr`/`wdata`，`wen=1` 打一拍写入，然后把 `raddr1`/`raddr2`
切到同一地址，看 `rdata` 是否读回刚才的值。

### 4.4 3.2 存储器

**子电路**：`ROM_64KB_32bit`、`RAM_64KB_32bit`、`RAM_pro`（读写自检）

| 子电路 | 引脚 |
| --- | --- |
| `ROM_64KB_32bit` | `address_byte`(16 入)、`enable`(1 入)、`cp`(1 入) → 数据输出(32) |
| `RAM_64KB_32bit` | `address_byte`(16 入)、`DataIn`(32 入)、`MemRead`、`MemWrite`、`cp` → 数据输出(32) |
| `RAM_pro` | `clk`、`Mcontrol`、`MemRead`、`MemWrite`、`address`(16)、`Datain`(32) → `DataOut`(32)、`Expect`(1) |

**容量**：16 位地址 × 32 位字宽 = 64 KB。ROM 里预置了一组测试数据，方便直接观察：

```
11111111  22222222  33333333  44444444
aabbccdd  ffff      ffff0000  12345678
deadbeef  cafebabe  88888888  99999999
```

**怎么看**：`RAM_pro` 是自检电路——先按要求写入数据，再读回来和期望值比较，
`Expect` 为 1 表示读写结果一致。RAM 上电后是全 0，需要自己写进去。

### 4.5 3.3 ALU

**子电路**：`ALU`（`main` 是带数码管的演示电路）

| 子电路 | 引脚 |
| --- | --- |
| `ALU` | `source1`(32 入)、`source2`(32 入)、`alu_control`(3 入) → `result`(32 出)、`zero`(1 出) |

**实现**：内部有加法器、减法器、OR 门、比较器（用于 SLT）、移位器（配位扩展器），
全部结果送进一个 **8 选 1 多路选择器**，由 3 位 `alu_control` 选择输出；
同时比较运算结果是否为 0，给出 `zero` 标志供分支指令使用。

**怎么看**：打开 `3.3-ALU模块.circ` 的 `main`，输入两个 32 位操作数和一个 3 位控制码，
数码管会同时显示操作数和结果；把控制码改成 §6 表里的值，就能逐个验证运算。

### 4.6 3.4 控制器

**子电路**：`cu`（主控制器）、`alu_control`（ALU 控制器）；`main` 是演示电路
（`opcode` + `func` → `Aluop`）

| 子电路 | 引脚 |
| --- | --- |
| `cu` | `opcode`(6 入) → `RegDst`、`ALUSrc`、`Branch`、`MemRead`、`Memwrite`、`Regwrite`、`MemtoReg`、`EXtop`、`stop`(各 1 出) |
| `cu` | 同时输出 `ALUop`(3 出) |
| `alu_control` | `func`(6 入)、`ALUop`(3 入) → `ALUcontrol`(3 出) |

**实现（硬布线）**：`cu` 内部用 7 个 6 位比较器，把 `opcode` 分别与下面的常量比较，
再用与/或/非门组合出各个控制信号：

| 指令类型 | opcode（十六进制） |
| --- | --- |
| R 型 | `0x00` |
| LUI | `0x0f` |
| ORI | `0x0d` |
| BNE | `0x05` |
| LW | `0x23` |
| SW | `0x2b` |
| STP | `0x3f` |

`alu_control` 用另外 3 个比较器把 `func` 与 `0x21`(addu)、`0x22`(sub)、`0x2a`(slt)
比较，再结合 `ALUop` 生成 3 位 `ALUcontrol`（详见 §6）。

### 4.7 4.1 单周期 CPU

**顶层**：`main`，只有 `clk`(1 入)、`reset`(1 入) 两个引脚，内部的 PC 自己跑。

**组成**：把前面几个模块连起来，再加上辅助逻辑：

| 子电路 | 作用 |
| --- | --- |
| `Count` | PC：16 位计数器（寄存器 + 加法器 + 常量），`reset` 清零，`stop` 后停住 |
| `Add4` | 32 位加法器 + 常量 `0x4`，算 PC+4 |
| `shift_left_2` | 分支偏移左移 2 位，用「分线器 + 低位补 0」实现 |
| `EX_control` | 立即数扩展：按 `EXtop` 在零扩展和符号扩展之间二选一 |
| `CU` / `ALU_control` | 译码，产生全部控制信号 |
| `ALU` | 执行运算，输出 `result` 和 `zero` |
| `MIPS_32x32_reg` | 通用寄存器组 |
| `ROM` / `RAM` | 指令存储器（14 位字地址 × 32 位）和数据存储器（14 位字地址 × 32 位） |

**执行过程**（一条指令一个时钟周期）：

1. 用 PC 从 ROM 取出指令；
2. `CU` 按 `opcode` 产生控制信号，`ALU_control` 按 `func` 细化出 ALU 控制码；
3. 从寄存器堆读操作数，必要时用扩展后的立即数；
4. ALU 运算；如果是 `bne` 且 `zero=0`，把分支目标（PC+4 加左移后的偏移）送进 PC；
5. `lw`/`sw` 访问数据存储器；`Regwrite` 有效时把结果写回寄存器堆；
6. 取到 `stp`（`0xFC000000`）时 `stop` 拉高，PC 停止更新，程序结束。

### 4.8 4.2 流水线 CPU

**顶层**：同样是 `clk`、`reset`。在单周期的数据通路上插入 4 组流水寄存器，
把执行过程切成 **IF / ID / EX / MEM / WB** 五级。

| 流水寄存器 | 主要引脚（节选） |
| --- | --- |
| `IFID` | `NPC_IN`(32)、`instruct_In`(32)、`ID_BLock`(1) → `NPC_OUT`、`instruct_out` |
| `IDEX` | `control_in`(16)、`RegDst_in`(5)、`IDEX_Rs`(5)、`IDEX_Rt`(5)、`func_in`(6)、`ALUsrc1_in`(32)、`ALUsrc2_in`(32)、`Imm_in`(32) → `control_out`、`RegDst_out`、`RS_out`、`RT_out`、`func_out`、`ALUsrc1_out`、`ALUsrc2_out`、`imm_out` |
| `EXMEM` | `control_in`(16)、`ALUout_putin`(32)、`RTtoMem_in`(32)、`RegDst_in`(5) → `control_out`、`ALUout_putout`、`RTtoMem_out`、`RegDst_out` |
| `MEMWB` | `control_in`(16)、`ALUout_putin`(32)、`LMData_in`(32)、`RegDst_in`(5) → `control_out`、`ALUout_putout`、`LMdata_out`、`RegDst_out` |

| 冒险处理单元 | 引脚 |
| --- | --- |
| `Forwarding_controlA` | `EXMEM_regw`、`MEMWB_regw`、`EXMEM_rd`(5)、`MEMWB_rd`(5)、`IDEX_Rs`(5) → `c1` (前推选择) |
| `Forwarding_controlB` | 同上，比较对象换成 `IDEX_Rt`(5) → `c2` |
| `Hazard` | `IDEXMemRead`、`IFID_Rs`(5)、`IFID_Rt`(5)、`IDEX_RT`(5)、`EXMEMM_Memread`、`EXMEMM_rt` → `stall` |

细节见 [§8 五级流水线](#8-五级流水线)。

## 5. 指令集与编码

指令字 32 位，格式为 MIPS 标准的 R 型 / I 型。控制器的 `opcode` 取指令的
`[31:26]`，`func` 取 `[5:0]`。

| 指令 | 类型 | opcode | func | 含义 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `addu` | R | `000000` | `100001` | `rd = rs + rt` | 加法，不处理溢出 |
| `sub` | R | `000000` | `100010` | `rd = rs - rt` | 不处理溢出 |
| `slt` | R | `000000` | `101010` | `rd = (rs < rt) ? 1 : 0` | 有符号比较 |
| `lui` | I | `001111` | — | `rt = imm << 16` | 立即数装高 16 位 |
| `ori` | I | `001101` | — | `rt = rs OR imm` | 立即数零扩展后按位或 |
| `bne` | I | `000101` | — | `if (rs != rt) PC = PC+4 + offset×4` | 用 ALU 减法 + `zero` 判断 |
| `lw` | I | `100011` | — | `rt = mem[base + offset]` | 地址按字对齐 |
| `sw` | I | `101011` | — | `mem[base + offset] = rt` | 地址按字对齐 |
| `stp` | — | `111111` | — | 停机 | 机器码 `0xFC000000`，拉高 `stop` |

立即数扩展规则：`lui`、`ori` 用**零扩展**（`EXtop=0`）；`lw`、`sw`、`bne`
用**符号扩展**（`EXtop=1`）。

## 6. 控制信号与 ALU 控制码

### 6.1 主控制器输出的控制信号

| 信号 | 位宽 | 含义 |
| --- | --- | --- |
| `RegDst` | 1 | 写回目标寄存器：0 → `rt`，1 → `rd` |
| `ALUSrc` | 1 | ALU 第二操作数：0 → 寄存器，1 → 扩展后的立即数 |
| `Branch` | 1 | 分支使能（`bne` 命中时改 PC） |
| `MemRead` | 1 | 数据存储器读使能 |
| `Memwrite` | 1 | 数据存储器写使能 |
| `Regwrite` | 1 | 寄存器堆写使能 |
| `MemtoReg` | 1 | 写回数据：0 → ALU 结果，1 → 存储器读出的数据 |
| `EXtop` | 1 | 立即数扩展方式：0 → 零扩展，1 → 符号扩展 |
| `stop` | 1 | 停机，停止 PC 更新 |
| `ALUop` | 3 | ALU 粗译码，交给 `alu_control` |

### 6.2 ALU 译码（`ALUop` + `func` → `ALUcontrol`）

| 指令 | 类型 | opcode | `ALUop` | `func` | ALU 动作 | `ALUcontrol` |
| --- | --- | --- | --- | --- | --- | --- |
| `addu` | R | 000000 | 010 | 100001 | 加法 | 000 |
| `sub` | R | 000000 | 010 | 100010 | 减法 | 001 |
| `slt` | R | 000000 | 010 | 101010 | 比较置位 | 011 |
| `lui` | I | 001111 | 100 | — | 高位加载 | 100 |
| `ori` | I | 001101 | 011 | — | 逻辑或 | 010 |
| `bne` | I | 000101 | 001 | — | 减法（看 `zero`） | 001 |
| `lw` | I | 100011 | 000 | — | 加法（算地址） | 000 |
| `sw` | I | 101011 | 000 | — | 加法（算地址） | 000 |
| `stp` | — | 111111 | 000 | — | 无 | 000 |

对照：`ALUcontrol = 000` 加法、`001` 减法、`010` 逻辑或、`011` 比较置位、`100` 高位加载。

## 7. 单周期数据通路

```
        ┌─────────┐  指令   ┌──────────────┐
 PC ───►│   ROM   ├────────►│ CU + ALU_ctl │──控制信号─┐
  ▲     └─────────┘         └──────────────┘           │
  │                                                     ▼
  │   ┌───────┐  rs/rt  ┌──────────────┐  ┌───────┐  ┌────────┐
  └───┤ Add4  │◄────────┤ 寄存器堆      ├─►│  ALU  ├─►│  RAM   │
      └───────┘         └──────▲───────┘  └───┬───┘  └───┬────┘
                               │              │ 写回      │
                               └──────────────┴──────────┘
```

要点：

- PC 由 `Count` 给出，`Add4` 算 PC+4，`shift_left_2` 算分支偏移；
- 寄存器堆读地址来自指令的 `rs`/`rt`，写地址由 `RegDst` 在 `rt`/`rd` 之间选择；
- ALU 的第二操作数由 `ALUSrc` 在寄存器值和立即数之间选择；
- 写回数据由 `MemtoReg` 在 ALU 结果和存储器数据之间选择；
- `zero` 参与分支判断，`stop` 让 PC 停止，程序结束。

## 8. 五级流水线

### 8.1 流水线寄存器

每一级之间用寄存器把「数据 + 控制信号」一起打包传下去：`IFID`、`IDEX`、`EXMEM`、
`MEMWB`。其中 `IDEX` 里保留了 `func`、寄存器号、两个源操作数和扩展后的立即数
（避免后面再回头去取），`EXMEM`/`MEMWB` 里保留 ALU 结果、要写入存储器的数据和
目的寄存器号（前推和写回都要用）。

### 8.2 数据前推（Forwarding）

`Forwarding_controlA` / `Forwarding_controlB` 分别针对当前 EX 级的两个源寄存器
`IDEX_Rs` / `IDEX_Rt`，检查前面两级的结果是否能直接拿来用：

- 若 `EX/MEM` 级要写寄存器（`EXMEM_regw=1`）且目的寄存器 `EXMEM_rd` 与当前源寄存器
  **相同且不为 0** → 选择 EX/MEM 的 ALU 结果（`c1`/`c2` 置位）；
- 否则若 `MEM/WB` 级要写寄存器（`MEMWB_regw=1`）且 `MEMWB_rd` 与当前源寄存器相同
  → 选择 MEM/WB 的写回数据；
- 都不满足就用寄存器堆读出的原值。

选择结果通过 `ALUsrc1_in/out`、`ALUsrc2_in/out` 这些多路选择器作用到 ALU 的输入端，
这样相邻指令之间的数据依赖就不用停顿了。

### 8.3 load-use 冒险的暂停

`lw` 的数据要到 MEM 级结束才拿得到，紧跟其后就用这条数据的指令无法靠前推解决。
`Hazard` 单元检测：EX 级是 `lw`（`IDEXMemRead=1`）**且**它的目的寄存器 `EXMEMM_rt`
等于 IF/ID 级要用的 `IFID_Rs` 或 `IFID_Rt` 时：

- 拉高 `stall`；
- PC 和 `IFID` 寄存器保持原值（冻结），`IDEX` 插入一个气泡；
- 一个周期后再继续，此时前推已经能把 `lw` 的结果送到 ALU。

### 8.4 分支

分支指令在 ID 级就用比较器比较 `IFID_Rs` 和 `IFID_Rt` 的值，命中时把
`NPC`（下一条指令地址）改成分支目标送入 PC，同时把已经取进 IF/ID 的两条指令作废
（`ID_BLock` 等信号配合）。

## 9. 内置测试程序

两个 CPU 的 ROM 里都预置了程序，打时钟就能跑。

### 9.1 单周期 CPU（4 条指令）

```asm
地址  机器码      汇编                 说明
0x00  8c010000   lw   $1, 0($0)       从数据存储器地址 0 取值到 $1
0x04  ac010004   sw   $1, 4($0)       把 $1 存到地址 4
0x08  fc000000   stp                  停机
0x0c  ac010008   sw   $1, 8($0)       停机后不会执行（保留）
```

这段程序用来验证「取数 → 存数 → 停机」这条最基本的通路：观察 `lw` 之后 `$1` 的值、
`sw` 之后数据存储器内容的变化，以及 `stp` 之后 PC 是否停止。

### 9.2 流水线 CPU（17 条指令）

```asm
地址  机器码      汇编                  说明
0x00  34010001   ori  $1, $0, 1        $1 = 1
0x04  34020001   ori  $2, $0, 1        $2 = 1
0x08  34070004   ori  $7, $0, 4        $7 = 4（地址步长）
0x0c  34050100   ori  $5, $0, 0x0100   $5 = 256（循环上界）
0x10  3c080000   lui  $8, 0x0000       $8 = 0（基址）
0x14  01053021   addu $6, $8, $5       $6 = $8 + $5
0x18  00221821   addu $3, $1, $2       循环体：$3 = $1 + $2（斐波那契递推）
0x1c  34410000   ori  $1, $2, 0        $1 = $2
0x20  34620000   ori  $2, $3, 0        $2 = $3
0x24  ad020000   sw   $2, 0($8)        把结果写入数据存储器
0x28  8d040000   lw   $4, 0($8)        立刻读回 → 触发 load-use 冒险
0x2c  14440003   bne  $2, $4, +3       读回值不对就跳走（自检）
0x30  01074021   addu $8, $8, $7       $8 += 4
0x34  0106482a   slt  $9, $8, $6       $9 = ($8 < $6)
0x38  1520fff7   bne  $9, $0, -9       $8 还没到上界就回到 0x18
0x3c  fc000000   stp                   停机
0x40  14c0fff5   bne  $6, $0, -11      停机后的兜底分支（正常执行不到）
```

关注三点：

1. **0x18~0x20 的斐波那契递推**：`$1`、`$2`、`$3` 连续变化，寄存器堆的写-读
   依赖正好用来观察前推；
2. **0x28 的 `lw` 紧跟 0x2c 的 `bne`**：`bne` 要用 `lw` 刚读回来的 `$4`，这是典型
   的 load-use 冒险，正常应该看到 `stall` 拉高、流水线停顿一拍；
3. **0x38 的循环分支**：`slt` + `bne` 控制循环次数，可以用来观察分支在流水线里
   怎么清空错误取到的指令。

## 11. 二次开发建议

想在这个工程上继续做实验，可以从这些方向入手：

1. **加指令**：`beq`、`j`、`jal` —— 在 `cu` 里增加比较器和分支逻辑，在 PC 选择
   多路器上加一个入口即可；`j` 型指令还要处理目标地址的拼接。
2. **补 ALU 运算**：加 AND / XOR / 移位 —— 在 `ALU` 的 8 选 1 多路器上接新的输入，
   并同步更新 `alu_control` 的译码表。
3. **补测试向量**：Logisim-evolution 支持 `-w <向量文件>` 跑测试向量。给
   `3.4-控制器.circ` 的 `main`（`opcode`+`func` → `Aluop`）和 `ALU` 写一组向量，
   就能把译码表固化成回归测试，改电路后一键验证。
4. **对照 HDL**：Logisim-evolution 的 `FPGA` 菜单可以把电路导出成 VHDL/Verilog，
   用来和手写的 RTL 对照，或者拿去上板。
5. **补截图**：给每个电路导出一张 PNG 放进 `docs/images/`，README 会更直观。

## 12. 常见问题

**Q：打开电路后一堆红叉 / 提示元件不存在？**
A：版本不对。请用 Logisim-evolution **3.9.0**，不要用老版 Logisim。

**Q：需要先安装 Java 吗？**
A：用仓库里的 `tools/logisim-evolution-3.9.0-x86_64.msi` 安装的话**不需要**，它自带
运行库。课程老文档里"先装 JDK 再跑 jar"的步骤是针对更老的版本的。只有命令行模式
（`scripts/verify-circuits.ps1`、`-t stats`）才需要系统里有 JRE 17+。

**Q：装的 3.9.0 但还是提示版本高于当前版本？**
A：确认打开的是 `circuits/` 里的文件，并且不是被旧版本另存过的副本。可以先用
`scripts/verify-circuits.ps1` 确认文件本身完好。

**Q：界面是英文，怎么切中文？**
A：`Edit → Preferences → International → Language` 选中文；或命令行加 `-o zh`。

**Q：时钟打了但电路不动？**
A：先看 `reset` 是不是一直是 1（复位状态会压住时钟）；再确认时钟接的是 `clk`/`cp`
而不是别的引脚；最后检查 `stop` 是否已经被拉高。

**Q：流水线 CPU 里的 `stall` 一直是高？**
A：说明一直检测到 load-use 冒险。检查 `IDEX` 里 `MemRead` 和 `rt` 是否跟着流水
寄存器正确传递，以及 `Hazard` 的寄存器号比较是否正确。

**Q：`scripts/verify-circuits.ps1` 报找不到 java？**
A：免安装版不带 `java.exe`，请装一个 JRE 17+，或者用参数指过去：
`pwsh -File scripts\verify-circuits.ps1 -Java "C:\path\to\java.exe"`。

**Q：Windows 上 MSI 装不上 / 没有管理员权限？**
A：用[免安装方式](#14-免安装方式可选)解包一份绿色版即可。
